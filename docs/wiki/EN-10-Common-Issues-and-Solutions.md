# 10 – Common Issues and Solutions

## Database Locked

**Symptom:** When saving or creating a new item, an error message appears stating that the database is busy or locked.

**Cause:** Another user is performing a write operation at the same moment, or a previous process did not close correctly.

**Solutions:**

1. **Wait and try again.** DataFlow automatically waits up to 10 seconds before reporting the error. If the error appears afterwards, retry after a few seconds — the conflict resolves itself in most cases.

2. **Check that all users have closed DataFlow.** If an instance was left open on another computer and not properly terminated (e.g. the computer was force-powered off), a residual lock file may be present.

3. **Look for residual WAL temporary files.** The `DataFlow/Database/` folder may contain `dataflow_db.db-wal` and `dataflow_db.db-shm` files. Under normal conditions these exist while the application is open and are incorporated into the database upon closing. If they persist after all users have closed DataFlow, it means the last session ended abnormally. Open and close DataFlow on any workstation to complete the WAL checkpoint.

## My Own RFQ Opens in Read-Only Mode

**Symptom:** Opening one of your own RFQs shows the red read-only banner.

**Possible cause:** The username on the current installation does not match the username recorded on the RFQ. This can happen if DataFlow was reinstalled on a new computer with a slightly different name, or if the language was changed and the system regenerated the username.

**Solution:** Check the current username in **⚙️ Settings** and compare it against the value shown in the "User" column of the RFQ. If they do not match, contact support to update the username field on the affected RFQ.

## Attachments Won't Open

**Symptom:** Clicking "Open Selected" in the attachment window does nothing, or an error appears.

**Cause 1 – File not found:** The attachment points to a relative path that no longer exists (e.g. the `Attachments/` folder was moved or renamed).

**Solution:** Verify that the `DataFlow/Attachments/{RFQ number}/` folder exists and contains the file. If the folder was moved, realign the DataFlow location in Settings.

**Cause 2 – No application associated with the file type:** The operating system has no default application for that file extension.

**Solution:** Install an appropriate application (e.g. Acrobat Reader for PDFs) and set it as the default for that extension.

**Cause 3 – File is on an unreachable network location:** The database is shared and the `Attachments/` folder is on a server that is currently unavailable.

**Solution:** Check the network connection and try again.

## Error During Excel Import

**Symptom:** Clicking "Import from Excel" shows an error, or rows are not imported correctly.

**Possible causes:**

- The Excel file does not match the expected format (columns in the wrong order, missing headers).
- The file is in an old format (`.xls`) instead of `.xlsx`.
- The file is open in Excel on another computer (read lock).

**Solutions:**

1. Use the Excel file generated by DataFlow's Export Excel function as the template for imports.
2. Make sure the file is in `.xlsx` format.
3. Close the Excel file (if open elsewhere) before importing.

## KPI Values Appear Incorrect or Incomplete

**Symptom:** The KPI Dashboard shows values that differ from what is expected, or events seem to be missing.

**What to check:**

1. **Check the active time filter.** A year filter set to the wrong year, or a rolling filter (e.g. 3M) that excludes older events, can reduce the totals. Click **All** to see all data with no limits.

2. **Remember that the filter acts on economic competence, not on the event date.** An event created last November with a 12-month distribution contributes to this year's KPIs for the distribution months that fall in the current year.

3. **Check the % Realisation of events.** If Actual Savings are much lower than Theoretical, verify that the "% Realisation" field on the events has not been set to 0 or a very low value.

---

## The Application Is Slow to Start

**Likely cause:** The DataFlow folder is located on a slow or unavailable network. On first access, DataFlow must open the database and verify its integrity.

**Solutions:**

1. Check the speed of the network connection to the shared folder.
2. If shared mode is not needed, move the database to a local drive.

---

## Special Characters in Supplier Names Are Removed

**Symptom:** When typing certain characters in the search field (apostrophe, quotation marks, backslash, angle brackets), they are automatically removed with a warning.

**Reason:** DataFlow filters characters that could cause problems in search queries. The message informs the user that the input has been sanitised.

**Solution:** Use only alphanumeric characters and spaces when searching. If a supplier name contains special characters, search for a portion of the name without them (e.g. search for "Smith" instead of "Smith & Sons").

## Restoring Data from a Backup

To restore a previous backup:

1. Close DataFlow on all workstations.
2. Rename the current file: `dataflow_db.db` → `dataflow_db.db.old`
3. Copy the backup file into the `DataFlow/Database/` folder, renaming it `dataflow_db.db`.
4. Restart DataFlow.

> Before overwriting the current database with a backup, make sure you are not discarding data entered after the backup was taken. The operation cannot be undone once the old file is deleted.
